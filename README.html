giti

The surgical Git insertion tool. Clone, replace, commit, push, and cleanup—all in one command.

Overview

giti is a Go-based CLI utility designed to make quick, targeted updates to remote Git repositories without the hassle of maintaining a local clone.

It automates the entire lifecycle of a "quick fix": cloning into a temporary unique directory, swapping out a file or directory (from your local disk or system clipboard), committing the change, pushing to origin, and deleting the temporary clone.

📋 Clipboard Support

Push code directly from your clipboard to a remote file. No temporary files required.

📂 Directory Swapping

Completely overwrite a remote directory with a local one recursively.

🧹 Auto-Cleanup

Automatically removes the cloned repository after the push is successful (or if it fails).

🔗 Smart URL Handling

Automatically normalizes github.com/user/repo shortcuts to full HTTPS URLs.

Installation 

# 1. Clone the repository
git clone https://github.com/phillip-england/giti.git
cd giti

# 2. Install dependencies
go mod tidy

# 3. Build the binary
go build -o giti main.go

# 4. (Optional) Move to path
sudo mv giti /usr/local/bin/

Note: Ensure you have Git installed and your credentials (SSH keys or Credential Helper) configured, as giti runs standard git commands.

Usage

The basic syntax requires three arguments:

giti <repo-url> <source> <replace-path>

Scenario 1: Paste from Clipboard

Update a file in the remote repo using the text currently in your clipboard.

giti github.com/user/project clipboard ./README.md

Scenario 2: Single File Replacement

Take a local file and overwrite a specific file in the remote repo.

giti github.com/user/project ./local-config.json ./config/settings.json

Scenario 3: Directory Overwrite

Replace an entire folder in the remote repo with a local folder.

giti github.com/user/project ./dist ./public_html

Technical Details

  • Built with Go 1.25.5+.
  • Dependencies: github.com/atotto/clipboard for cross-platform clipboard access.
  • Creates unique temporary directories (e.g., repo_1, repo_2) to prevent conflicts if multiple instances run.
  • Uses standard os/exec to run git commands, ensuring compatibility with your local git configuration.
